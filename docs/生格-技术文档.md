# 「生格」技术文档（App 版）

> 产品定位：生命感知 + 微小人生探索工具
> Slogan：不直接告诉你人生意义，陪你慢慢找到属于自己的意义。
> 形态：**Flutter 双端 App（主体）+ 微信小程序海报工厂（传播器）**
> 架构基调：**本地优先（Local-first），云同步为可选择的订阅权益**
> 文档版本：v2.0（App 版，替代原小程序方案）｜ 日期：2026-10-15
> 关联文档：《生格-App战略分析报告.md》《生格-合规与标准化建设方案.md》

---

## 1. 项目概述

### 1.1 产品一句话

把宏大的虚无问题，拆解成每天可感知、可记录、可体验的小事。用户通过「生命方格」双视角看板（倒计时 / 收集）、每日轻提问日记、微小人生实验和愿望仓库，重建对生活的掌控感。

### 1.2 核心设计原则（技术侧必须遵守）

| 原则 | 技术含义 |
|------|----------|
| 不给标准答案 | 系统只做提问、汇总、整理线索，**绝不由 AI/规则生成"你的人生意义"结论**（Code Review 强制项） |
| 低压力、无惩罚 | 无打卡任务、无积分、无断签惩罚、无强制推送（每月 ≤2 条且全部可关） |
| 心理安全红线 | 端侧风险识别 + 危机热线弹窗 + 服务端审核兜底，严禁心理诊疗功能（SOP 见合规方案 2.3） |
| 克制调性 | 极简低饱和 UI，无大红大绿，无励志热血文案 |
| 本地优先 | 日记等 L3 高敏感数据默认仅存本机；"数据仅存于本机"是产品卖点，也是合规优势 |

### 1.3 MVP 范围（App 第一版只做 4 件事）

1. **生命方格看板**（双模式：倒计时 / 记忆收集）
2. **每日轻提问记录**（本地存储）
3. **愿望仓库**
4. **锁屏/桌面小组件**（剩余天数 / 今日一格，App 形态的核心差异化）

后续迭代：云同步（订阅）→ 微小人生实验 → 线索汇总 → 导出与实体周边 → 家庭篇。

## 2. 技术选型

### 2.1 总体方案：Flutter + 本地优先

| 层 | 选型 | 理由 |
|----|------|------|
| 客户端 | **Flutter 3.x**（iOS + Android 一套代码） | 单开发者产能最优；CustomPainter 完全胜任方格 Canvas 渲染；社区成熟 |
| 本地数据库 | **SQLite + drift**（Flutter 生态） | 类型安全、支持迁移、响应式查询；本地优先架构的地基 |
| 状态管理 | Riverpod | 轻量、可测试 |
| 小组件 | iOS：WidgetKit（Swift 桥接）；Android：Glance / AppWidget | 锁屏小组件是 MVP 差异化功能 |
| 服务端 | **极薄后端**：Node.js (NestJS) 或 Python (FastAPI) + MySQL 8.0 + Redis 5.0 | 只承担三件事：账号同步、内容审核兜底、热线配置下发。开发期可用本地 MySQL/Redis 环境联调 |
| 云同步 | 端到端加密增量同步（订阅权益） | 卖点型付费点：用户为自己的记录付费 |
| 内容审核 | 服务端 `msgSecCheck` 等价方案（云同步开启时） | 合规兜底，见 §6.2 |

### 2.2 本地优先的数据流

```
用户操作 → 端侧 SQLite（权威数据源）→ UI 响应式刷新
                │
                ├─ 断网：一切功能照常（零网络依赖）
                └─ 开启云同步（订阅）→ 加密增量上传 ↔ 服务端
```

> 关键决策：**App 无账号也能完整使用**（游客模式 = 纯本地）。账号与云同步只在用户需要时出现。这同时解决隐私合规（最小化收集）、弱网体验与"随时打开随时关掉"。

## 4. 数据模型设计

数据分两层：**端侧 SQLite（权威）** 与 **服务端 MySQL（仅同步密文与配置）**。字段语义与原版一致，存储位置按数据分级（见合规方案 §3.3）调整。

### 4.1 端侧 SQLite（drift 表定义，权威数据源）

```dart
// 用户档案（本地单例，游客模式即用）
Users(
  id: int auto,
  birthYear: int?, birthMonth: int?, birthDay: int?,   // 可选，用于方格
  lifeExpectancy: int default 80,                       // 可自定义
  viewMode: int default 0,                              // 0倒计时 1收集
  meaningStatement: String?,                            // 意义陈述,可改可删
  createdAt, updatedAt
)

// 生命方格日记录：每天一格，只存有记录的格子
LifeCells(
  id: int auto,
  cellDate: DateTime,          // 唯一索引 (cellDate)
  tag: String?,                // 用户自选标签
  moodType: int?,              // 1滋养 2耗竭 null未标记
  memory: String?,             // 存入的一段人生素材(≤500字)
  createdAt, updatedAt
)

// 日记（L3 最高敏感：仅本机，云同步时端到端加密）
DiaryEntries(
  id: int auto,
  questionId: int?, customQuestion: String?,  // 今日轻提问或自写
  content: String,
  cellDate: DateTime,          // 归档到哪一天的方格
  riskLevel: int default 0,    // 端侧引擎结果: 0安全 1疑似 2高危
  createdAt, updatedAt
)

// 愿望仓库
WishItems(
  id: int auto,
  content: String,             // 这辈子想体验的小事
  status: int default 0,       // 0想体验 1已体验 2悄悄放弃
  doneAt: DateTime?, doneNote: String?, cellDate: DateTime?,
  createdAt, updatedAt
)

// 同步队列（本地优先架构的关键件）
SyncQueue(
  id: int auto,
  tableName: String, rowId: int, operation: String,  // upsert/delete
  updatedAt: DateTime, syncedAt: DateTime?
)
```

### 4.2 服务端 MySQL（仅同步与配置，无明文 L3 数据）

```sql
-- 云同步密文存储（端到端加密，服务端不可解）
CREATE TABLE `sync_blob` (
  `id`          BIGINT PRIMARY KEY AUTO_INCREMENT,
  `account_id`  BIGINT NOT NULL,
  `device_id`   VARCHAR(64) NOT NULL,
  `blob`        LONGBLOB NOT NULL COMMENT 'E2E加密的增量数据',
  `rev`         BIGINT NOT NULL COMMENT '修订号',
  `created_at`  DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY `uk_acct_rev` (`account_id`, `rev`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 轻提问题库（配置下发，全量公共内容）
CREATE TABLE `daily_question` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `content` VARCHAR(200) NOT NULL COMMENT '如: 今天哪一刻,你觉得活着还不错?',
  `category` VARCHAR(32) DEFAULT NULL,
  `is_active` TINYINT NOT NULL DEFAULT 1
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 危机热线配置（每季度人工核验，运维日历跟进）
CREATE TABLE `hotline_config` (
  `id` BIGINT PRIMARY KEY AUTO_INCREMENT,
  `region` VARCHAR(32) NOT NULL DEFAULT 'CN',
  `name` VARCHAR(100) NOT NULL,
  `phone` VARCHAR(32) NOT NULL COMMENT '如: 12356',
  `hours` VARCHAR(64) DEFAULT '24小时',
  `is_active` TINYINT NOT NULL DEFAULT 1
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

> 设计要点：服务端**没有**日记明文表、没有用户画像表——从 schema 层面保证"服务端不可读用户隐私"，这是隐私政策里可以白纸黑字承诺的架构事实。

## 5. 接口设计（薄后端，全部可选）

统一前缀 `/api/v1`。游客模式下除题库/热线配置外全部接口不调用。

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/auth/guest` | 生成匿名账号（云同步用，可选） |
| POST | `/sync/push` | 上传加密增量 blob（端到端加密，服务端只存密文） |
| POST | `/sync/pull` | 拉取 rev 之后的增量 |
| GET  | `/config/questions` | 轻提问题库下发（App 本地缓存 30 天） |
| GET  | `/config/hotline` | 危机热线配置下发 |
| POST | `/moderation/check` | （仅云同步开启时）文本审核兜底 |

响应格式：`{ "code": 0, "msg": "ok", "data": {} }`

### 5.1 线索汇总（端内计算，无接口）

滋养/耗竭统计**完全在端侧**由 drift 查询完成，输出仅含计数与线索式文案模板（"这或许是你意义的线索"）。App 内不存在 `conclusion` / `meaning` 字段的数据结构——从类型系统上杜绝越界（延续原版契约约束）。

## 6. 关键技术方案

### 6.1 生命方格渲染（Flutter）

- 数据：默认周格（80 年 × 52 周 = 4160 格），可切天格（29200 格）。
- 实现：`CustomPainter` + `RepaintBoundary`。首帧只绘最近 2 年，列表滚动/缩放时增量重绘；整画布离屏缓存。
- **双模式 = 同一数据的两种着色策略**：
  - 倒计时模式：已过格低饱和灰，剩余格极浅底色，顶部温和进度条；
  - 收集模式：有记录的格按标签着低饱和色，无记录格透明。
- 手势：点按格子查看当天记录/补记；长按进入标签编辑。
- 格子坐标换算封装为纯函数 `dateGrid.dart`（`日期 ↔ (周,年) ↔ 画布坐标`），单元测试全覆盖——这是全 App 数学上最容易出错的地方。

### 6.2 锁屏/桌面小组件（MVP 差异化）

- iOS：WidgetKit + App Group 共享 SQLite 数据副本；支持锁屏 accessory（剩余天数）与桌面中尺寸（迷你方格 + 今日状态）。
- Android：Glance（Jetpack Compose for Widgets），桌面小部件 + 通知渠道常驻可关。
- 刷新策略：`widget更新`每日 0 点与记录写入时触发；**绝不**用小组件制造焦虑（只显示天数与今日一格状态，无倒计时恐吓文案）。

### 6.3 风险识别与危机干预（三层防线）

1. **端侧敏感词引擎**：本地词库（内置 + 可远程更新），命中高危词 → Redis 风格的本地计数（`riskCount/date`）；
2. **服务端审核兜底**：仅当用户开启云同步且内容参与同步时，走服务端内容安全接口；
3. **分级响应**（与《合规方案》SOP 完全一致）：
   - level 1 疑似：正常保存不提示，标记观察；
   - level 2 高危（单次命中）：立即弹危机弹窗——固定文案 + 12356 热线拨打按钮，该条内容停止展示，写入本地风控日志（留痕 ≥6 个月，仅风控用途）；
   - level 3 多次高危：弹窗升级；
   - **绝不做**：AI 开导、安抚话术生成、任何形式的诊疗。

### 6.4 同步与冲突策略（订阅功能）

- 端侧 `SyncQueue` 记录未同步变更；网络可用时按序推送加密 blob；
- 冲突策略：记录类按"每用户每格每天一条"粒度 `last_write_wins`；配置类（view_mode）以服务端为准；
- 换机场景：新设备登录 → 端到端密钥由用户口令派生（服务端永不接触明文密钥）→ 拉取解密；同时保留**本地导出备份文件**（JSON/PDF）双保险。

## 7. 安全、合规与隐私（落地架构）

| 项目 | 方案 |
|------|------|
| 心理合规 | 免责声明置于首次启动与关于页；产品自称"自我记录工具"，文案过黑白名单（合规方案 §2.4） |
| 内容安全 | 端侧引擎 + 云同步时服务端审核兜底；无社区、无公开分享（MVP） |
| 隐私收集 | 最小化：游客模式零收集；生日可选；不收集位置/通讯录/剪贴板；隐私政策逐项声明 |
| 数据存储 | L3（日记）默认仅本机；云同步 E2E 加密、服务端不可解；账号注销 → 15 天反悔期后物理删除（政策写明） |
| 未成年人 | 未满 14 周岁阻断；14~18 岁风控等级提高、不推送付费内容 |
| 商业合规 | 免费底座（方格/双视角/日记/愿望永久免费）+ 导出 PDF/订阅/实体周边；永不做广告、课程、付费社群 |

| 阶段 | 内容 | 验收标准 |
|------|------|----------|
| P0（1~2月） | 合规预备：公司主体、软著、商标、ICP/App 备案、隐私政策、PIA | 材料齐备（开发并行） |

### 8.3 关键指标（验证需求）

- **方格记录连续性**：30 天内有记录天数 ≥10 天的用户占比（北极星）
- 次周留存（低压力产品预期不高，看资产沉淀）
- 海报分享→下载转化率（P2 核心增长指标）
- 小组件添加率（健康度代理指标：用户愿意把生格放上桌面 = 信任度）

## 10. 附录：产品底层逻辑（技术实现的锚点）

> 接纳迷茫 → 记录日常里的滋养/消耗感受 → 通过微小实验测试自己的偏好 → 积累线索，自己提炼价值方向 → 在生活里持续验证，随时修改。
>
> APP 全程是"提问者、记录员、线索整理人"，绝不充当人生导师，不给标准答案。

**技术团队的三个"绝不"（Code Review 强制检查项）**：
1. 绝不在任何接口/文案/AI 逻辑中生成"你的人生意义是 X"这类结论；
2. 绝不加入打卡、积分、断签惩罚、强制推送；
3. 绝不做心理疏导/开导功能，危机情况只做"提示 + 转介专业热线"。
