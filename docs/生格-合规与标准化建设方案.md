# 「生格」合规与标准化建设方案

> 总纲级文档：App 开发全周期必须遵守的合法合规、标准化、正规化、健康化要求。
> 定位原则：**合规不是成本，是这个产品的生命线**——产品触碰情绪敏感区，任何一次合规事故都是致命的。

## 一、法律合规框架（四法 + 备案体系）

### 1.1 必须遵守的法律法规

| 法律法规 | 对本产品的具体要求 |
|---------|------------------|
| **《网络安全法》** | 网络实名（游客模式无账号不涉及；用户可选开通账号时采用微信/手机号登录即满足）、日志留存不少于 6 个月、等级保护定级备案（初期用户量小可暂缓，超过阈值需二级等保） |
| **《个人信息保护法》（PIPL）** | 最小必要、单独同意（敏感信息）、隐私政策明示、账号注销、个人信息影响评估（PIA） |
| **《数据安全法》** | 数据分类分级管理（见第四节）、重要数据不出境 |
| **《未成年人保护法》** | 14 周岁以下未成年人个人信息属**敏感个人信息**，需监护人单独同意；产品内设年龄门槛 |
| **《广告法》** | 产品宣传文案禁用极限词与医疗暗示（详见 3.2） |
| **《精神卫生法》红线** | 严禁从事心理治疗、精神障碍的诊断与治疗——这是本产品最高优先级的法律红线 |

### 1.2 备案与资质清单（P0 阶段必须完成）

| 事项 | 说明 | 周期 | 优先级 |
|------|------|------|--------|
| 公司主体 | 注册有限公司（不建议个体户：无法入驻部分应用商店、无法开发票给企业客户） | 1~2 周 | P0 |
| 软件著作权 | App 软著证书，Android 商店上架硬性要求；同时注册「生格」第 9 类（软件）+ 第 42 类（SaaS）+ 第 16 类（印刷品/手账本）商标 | 软著 1~2 月（可加急）；商标 8~12 月（申请即用） | P0 |
| ICP 备案 | 域名 + 服务器备案（非经营性） | 2~4 周 | P0 |
| App 备案 | 2023 年起工信部强制，所有 App 分发前必须完成，与 ICP 备案关联 | 2~4 周 | P0 |
| ICP 经营许可证（EDI/ICP证） | **是否需要的关键判断**：若云同步/订阅属于"向用户提供在线数据处理服务并收费"，部分地区要求办理增值电信业务许可。稳妥做法：咨询属地通管局，MVP 若只走苹果 IAP + 商店内购、服务器仅做同步，多数情况下可先备案后办证 | 2~3 月 | P1 |
| 应用商店协议 | 华为/小米/OPPO/vivo/苹果开发者账号，企业主体认证 | 各 1~2 周 | P1 |

> **合规原则：宁可慢，不可错。所有资质办完之前，不公开发布、不收费、不做任何推广。**

## 二、产品合规设计（把合规做进架构里）

### 2.1 个人信息合规（PIPL 落地清单）

1. **收集最小化**：只收集openid（账号）+ 可选生日 + 用户主动输入的记录内容。不收集位置、通讯录、设备列表、剪贴板；
2. **隐私政策**：独立页面 + 首次启动弹窗单独同意；隐私政策中逐项列明"收集什么、为什么、存多久、给谁"；采用"个人信息清单"标准格式（工信部 164 号文要求）；
3. **敏感信息处理**：生日属敏感度较低信息，但**日记内容可能含情绪隐私**——设计上默认本地存储，云同步为用户显式开启的可选项；开启前二次确认；
4. **账号注销**：设置内一键注销，注销后服务端数据 15 天内物理删除（留 15 天反悔期需在政策中写明）；
5. **导出权与删除权**：提供全量数据导出（JSON/PDF），提供单条删除——既是 PIPL 要求，也是产品功能；
6. **PIA 评估**：上线前完成一次《个人信息保护影响评估报告》存档（法律要求，也是过审材料）。

### 2.2 未成年人保护

- 注册时年龄声明：未满 14 周岁不可使用（阻断）；14~18 周岁简化版体验 + 风控等级提高；
- 未成年用户触发危机干预时，弹窗文案额外提示"请告诉信任的家人或老师"；
- 不对未成年人推送任何付费内容。

### 2.3 心理安全 SOP（正式流程文件，全团队必须背下来）

```
触发 → 识别（敏感词引擎 + msgSecCheck/端侧等价方案）
  ├─ 疑似（level 1）：正常保存，不提示，风控标记观察
  ├─ 高危（level 2，单次命中）：立即弹窗危机提示
  │    文案固定："本产品仅为自我记录工具，不能替代专业心理帮助。
  │    如果痛苦难以承受，请立即联系：
  │    全国心理援助热线 12356（24小时）"
  │    提供「拨打」按钮；该条内容停止展示；写入风控日志
  ├─ 多次高危（level 3）：弹窗升级 + 停用 AI 类交互（若有）
  └─ 严禁事项：任何形式的 AI 开导/安抚话术/用户互相开导
日志：风控事件留痕 ≥6 个月，仅风控用途，不进入任何推荐/统计
```

> 热线号码每季度人工核验一次有效性，写入运维日历。

### 2.4 内容与文案合规

- **白名单词汇**：迷茫、感受、记录、体验、平静、观察、线索、陪伴；
- **黑名单词汇**（产品文案与商店描述一律不用）：抑郁、焦虑症、疗愈、治愈、心理治疗、诊断、干预、康复；
- **广告法自查**：不用极限词（最、第一、唯一、彻底解决）；不暗示医疗功效；不制造焦虑式营销话术（"再不记录就来不及了"这类文案永远不出现）；
- 上架商店描述模板中同时附《免责声明》：本产品为自我记录与时间感知工具，不提供医疗、心理、财务、法律专业建议。

## 三、标准化（软件工程规范）

### 3.1 研发流程标准

| 环节 | 标准 |
|------|------|
| 代码管理 | Git flow；main 分支保护；每次合并必须经过 review |
| 发布流程 | 版本号语义化（SemVer）；发布前三道检查：合规检查单 → 隐私检查单 → 风控检查单；Android 分商店灰度，iOS TestFlight 先行 |
| 测试标准 | 核心链路（方格渲染/记录存取/风控弹窗）必须有自动化测试；风控逻辑变更必须回归测试 |
| 文档标准 | 每个功能模块有设计文档；本方案中的合规要求写入 PR 模板检查项 |

### 3.2 Code Review 三条"绝不"（延续技术文档，升级为强制检查项）

1. 绝不在接口/文案/AI 逻辑中生成"你的人生意义是 X"结论；
2. 绝不加打卡、积分、断签惩罚、强制推送；
3. 绝不做心理疏导/开导功能——危机只做"提示 + 转介"。

### 3.3 数据分类分级（数据安全法落地）

| 级别 | 数据 | 管控 |
|------|------|------|
| L3 高敏感 | 日记内容、危机风控日志 | 默认仅本地存储；云同步端到端加密；运维人员不可见明文；泄露即重大事故 |
| L2 中敏感 | 生日、意义陈述、愿望 | 加密存储、最小化采集 |
| L1 一般 | openid、视角偏好、主题设置 | 常规加密 |

## 四、健康化（产品价值观的制度化）

### 4.1 《产品宪法》——公开的"不做什么"

把克制写成制度并公开在官网与 App 关于页，六条：

1. 永远不做广告；
2. 永远不做打卡、积分、连续记录惩罚；
3. 永远不替用户得出人生结论；
4. 永远不做心理诊疗与情感咨询；
5. 永远不出售用户数据；
6. 永远不制造焦虑式营销。

> 这六条既是价值观，也是合规护盾、也是品牌故事。WeCroak 拒绝广告换来《纽约时报》报道，验证了"克制即传播"。

### 4.2 健康化设计指标（纳入验收）

| 指标 | 健康标准 | 反例（禁止出现） |
|------|---------|----------------|
| 推送频次 | 每月 ≤2 条，全部可关 | 每日提醒"你还有 X 天" |
| 付费引导 | 每月 ≤1 次自然触达 | 付费墙、倒计时优惠、体力逼迫 |
| 文案情绪 | 接纳、平静 | "你的人生正在流逝"式恐吓 |
| 社交设计 | 无排行榜、无点赞 | 任何形式的比较机制 |
| 使用时长 | 不优化打开时长，优化"平静离开" | 信息流化、无限下滑 |

**核心健康化理念：这个产品优化的是"用户离开时的心情"，不是"用户停留的时长"。** 健康化指标与商业指标冲突时，健康化优先——并写进公司章程。

## 五、合规时间表（与执行路线对齐）

| 阶段 | 合规动作 |
|------|---------|
| P0（第1~2月） | 公司注册、软著申请、商标申请、ICP备案、App备案、隐私政策与用户协议起草（建议律师审阅）、PIA 评估 |

## 六、一句话总结

**对这个产品而言，合规、标准、正规、健康不是四件任务，而是同一件事的四个名字：值得信任。**

用户把最私密的感受交进来，信任就是唯一的护城河——所有合规投入，都是在给这条护城河挖深。
